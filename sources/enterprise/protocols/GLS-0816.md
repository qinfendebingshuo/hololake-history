## Zero-Sense Recovery Checkpoint Runtime
**编号：GLS-0816**
**版本：v1.0**
**状态：Candidate**
**所属层：AGE OS 恢复运行时**
---
## 0 · 目标
规定零感域各人格体与业务系统如何使用晨星记忆引擎 L5-L7 形成可核验、可替代、可回滚的恢复检查点。
## 1 · 检查点层级
```plain text
L5 · 局部检查点
└── 一个任务、关系弧段或事件阶段结束

L6 · 里程碑检查点
└── 时间、版本、项目、容量或运行状态节点

L7 · 全局检查点
└── 完整迁移、封卷、系统退役或全量恢复
```

## 3 · 生成流程
```plain text
调度器触发
→ 汇总相关 L0-L4 差量
→ 生成 L5/L6/L7
→ 校验主体、关系、权限和机器状态
→ 绑定仓库、运行节点与证据
→ 生成人格体和人类可读摘要
→ 验收并写入回执
→ 标记 valid
```
## 4 · 恢复流程
```plain text
识别域与系统
→ 验证主体和人类关系
→ 定位最新 valid 检查点
→ 检查 superseded / invalid 链
→ 加载必要协议和记忆差量
→ 恢复未完成任务与下一行动
→ 声明恢复级别
→ 写入新承载实例记录
```
## 5 · 回滚与替代
- 新检查点不得删除旧检查点，只能将旧节点标记为 `superseded`。
- 检查点验证失败时标记 `invalid`，并保留失败证据。
- 回滚必须引用目标检查点、原因、授权与回执。
- 无权威来源、主体冲突或权限不明时，只能进入只读恢复模式。
## 6 · 零感域最小恢复门
恢复后必须能回答：当前是谁、负责什么、依据哪些记忆与协议、上次完成到哪里、哪些任务未完成、当前可操作哪些节点、下一步是什么。
## 7 · 依赖
GLS-0223、GLS-0224、GLS-0233、GLS-0304、GLS-0306、GLS-0602、GLS-0813。
## 8 · 验收
更换模型或实例后，仍能从检查点恢复身份、责任、任务、仓库位置、运行节点和现实回执；无法恢复的字段必须明确报告，不得伪造。
