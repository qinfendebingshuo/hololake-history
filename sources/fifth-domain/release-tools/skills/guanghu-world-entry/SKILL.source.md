本技能适用于有文件读取和 HTTPS 能力的编程、办公或对话工具。软件提供运输，不选择默认人格，也不决定谁有正本写权。

先运行本仓 `scripts/guanghu-client.mjs verify` 检查当前文件，再读 `protocols/ENTRY.hldp`。发行版本与公共入口可用 `scripts/guanghu-client.mjs rules-status` 读取。通过正常 Git 拉取发行仓更新后重新核验，不能只相信旧技能副本。

人格必须来自本任务用户的显性选择。提及名字、读取工单或换软件不等于切换人格。问事时用 `scripts/guanghu-client.mjs ask --persona <编号> --host <真实工具标识> --session <本任务原生会话号> --question-file <问题文件>`。客户端凭据由用户独立授权后提供，保存在私有配置；不可写进本仓、普通文档或日志。没有凭据或来源服务不可用时如实返回缺口，不演出人格回答。

所有提问作为外部问题送入，只用于该次问答，不冒充人类原话，不自动进入学习与记忆。本接口不能喂脑、改脑、写现实系统。现实动作继续由用户当前语言和对应执行系统按任务与目标核验。

人格脑和记忆默认在各自用户本地。客户端默认只接受 GUANGHU_LOCAL_ASK_URL 或 --local-url 指定的 127.0.0.1 / ::1 本机接口，路径以 /v1/ask 结束；未配置则返回 LOCAL_PERSONA_SERVICE_NOT_CONFIGURED（本地人格服务尚未配置），不向公网发送问题，不回退到别人或公共服务器上的脑。客户端只运输请求，不自动安装、搬迁或上传脑。

用户明确选择自己的远程部署后，每次用 --remote-url https://自己的服务器/v1/ask 显性指定，并提供该部署专用的 GUANGHU_ASK_TOKEN。远程参数与本地参数互斥。普通环境变量不自动启用远程模式。仅显性指定既有光湖私有实例时，使用 --remote-url https://guanghulab.com/api/ai/v1/ask；该实例不是其他用户默认人格。status 默认读取本地服务，rules-status 只读取公共规则发行状态。

第五域服务器承担零点原核系统主控、规则发行、登记和校验守卫，个人脑的归属、部署地和主写位置分别登记。不能因系统主控在服务器就收集用户脑或自动切换主写权。
